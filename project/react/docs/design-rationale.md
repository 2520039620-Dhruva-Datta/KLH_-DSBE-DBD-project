# A compact entry, with depth where the work happens

AMAP keeps a small wordmark and the familiar departmental blue. Warm white surfaces, quiet borders and restrained shadows separate working areas. Lora gives the main headings a human voice; Source Sans 3 keeps forms, labels and dense registers readable. Both fonts are self-hosted with their SIL Open Font Licenses, from the [Google Fonts repository](https://github.com/google/fonts). There are no external font or asset requests at runtime.

The homepage answers three questions: what this is, what I can apply for, and how I follow the outcome. Its two primary actions lead to apply and track. Eight department cards contain the actual service rows, with documents, fees and timelines one click away. The four-step strip and academic attribution finish the page. Statistics walls, feature grids, architecture diagrams, illustrations and oversized search have been removed from this public entry; none helps a first-time applicant make that decision.

The interior retains the complete workflow and analytics. The queue has saved views with live counts, selection, explicit sorting and assignment. The register, user table, service table and officer ranking request filtered pages through API. Dashboard and report scopes apply to each chart and summary; counts come from the same stored records. Loading skeletons, busy buttons, selected rows, short count transitions, focus rings and keyboard chart tooltips communicate state without continuous animation. Reduced-motion preferences suppress animation.

The fixture contains 6,006 applications over three years, 600 citizens, 48 officers, two administrators and 460 grievances. Mulberry32, a schema version and a persisted generation anchor keep reloads reproducible. Store reconstructs the baseline and persists only changed or deleted rows, keeping thousands of sample records out of the localStorage quota. Only paged results receive full joined relations. The initial fixture is still demonstration data, not a record of real government activity.

Department and service cards come from data; adding a department or service needs no new component. Optional service attributes can be added behind the same list/get/save facade, while a future subtype table or department parent relationship can extend those entities without new per-service routes. SQL additions provide composite indexes and let grievances use the existing audit table. The original Phase 1 SQL remains available as `schema.phase1.sql`.

The live backend remains a separate next step: this React port preserves the archive’s contract, which differs from the retained root Express/MySQL app. A transport-compatible, authorized backend must replace demo persistence before this can become a deployed service.
